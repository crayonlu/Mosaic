# Server Development

The Mosaic production server is built with **Go** using **chi**, **pgx**, and
**goose**. This guide covers local development setup.

> Looking for the Rust tree? It lives in `server/` as a reference
> implementation and is not the deployed backend.

## Prerequisites

- Go 1.26+
- PostgreSQL 15+ with pgvector extension
- FFmpeg (optional, for video processing)

## Setup

### 1. Clone and enter the server directory

```bash
git clone https://github.com/crayonlu/Mosaic
cd Mosaic/server-go
```

### 2. Configure environment

```bash
cp .env.example .env
# Edit .env with your database credentials
```

### 3. Set up the database

Create a PostgreSQL database:

```bash
createdb mosaic
# or
psql -c "CREATE DATABASE mosaic;"
```

Enable the pgvector extension:

```bash
psql -d mosaic -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

### 4. Run the server

```bash
go run ./cmd/mosaic-server
```

The server will:

1. Read configuration from `.env`
2. Connect to PostgreSQL
3. Apply pending migrations through goose
4. Start listening on the configured port (default: 8080)

## Database Migrations

Migrations live in `server-go/migrations/` (just `migrations/` once you are in
that directory) and run automatically on startup via goose. Each migration is a
timestamped SQL file that must start with a `-- +goose Up` directive; a
`-- +goose Down` section is optional. The applied set is recorded in the
`goose_db_version` table. To add a new migration:

```bash
touch migrations/$(date -u +"%Y%m%d%H%M%S")_your_description.sql
```

Write the `-- +goose Up` SQL in the file. On the next server restart, it is
applied automatically. The Go tree mirrors the Rust tree's migrations and adds
the goose directives; the SQL bodies are the same.
